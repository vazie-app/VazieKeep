# Shared test vectors

Inputs and expected outputs that **every** implementation layer is checked against: `keep-core`
itself, the UniFFI bindings (Kotlin, Swift), and the WASM build used by the browser extension.

A format quirk fixed in one place must not silently differ in another. That's why vectors live here
and not inside a single crate or app.

## Layout

One directory per suite. Each suite has a `vectors.json` with a `suite` name, a `version`, and a
`vectors` array. Binary inputs are hex strings inside the JSON when they are small. Larger inputs
sit next to the JSON as files.

| Suite | Consumed by | Purpose |
| --- | --- | --- |
| `format-detection/` | `core/keep-core/tests/format_vectors.rs` | File signature and KDBX version detection |
| `kdbx4/` | `core/keep-core/tests/kdbx4_vectors.rs` (full); Android, desktop and Swift bridge tests (`aes256-argon2d.kdbx`) | KDBX 4.x read: ciphers, KDFs, content, negative cases |
| `autofill/` | Android unit and instrumentation tests (`AutofillRealCoreTest`, `AutofillDeviceTest`) | One vault of synthetic entries for the Autofill matching policy: exact, subdomain, parent, look-alike, public suffix, port, scheme, Unicode host, app-only, trashed |
| `keyfiles/` | `core/keep-core/tests/keyfile_vectors.rs` (full); FFI, WASM, Kotlin bridge and Android instrumentation tests | Password-only, key-file-only and password + key-file vaults; every KeePass key-file format |

Planned suites: vaults written by KeePassXC and KeePass 2.x, round-trip after writing, and merge
scenarios.

## `keyfiles/`

Generated by `tooling/test-vectors/generate_keyfiles.py` (pykeepass 4.2.0, Argon2d 1 MiB). Every
vault holds one entry, `Key File Entry` / `kf-user` / `kf-pass-synthetic`.

| File | Protected by | Notes |
| --- | --- | --- |
| `vault-password-only.kdbx` | `standard` password | |
| `vault-keyfile-only.kdbx` | `keyfile-v2.keyx` | |
| `vault-password-plus-keyfile.kdbx` | `standard` + `keyfile-v2.keyx` | |
| `vault-keyfile-xml-v1.kdbx` | `keyfile-v1.key` | XML 1.00, Base64 data |
| `vault-keyfile-binary32.kdbx` | `keyfile-binary32.key` | exactly 32 bytes, used as is |
| `vault-keyfile-hex64.kdbx` | `keyfile-hex64.key` | 64 hex characters |
| `vault-keyfile-hashed.kdbx` | `keyfile-hashed.bin` | 1000 arbitrary bytes, SHA-256 |
| `keyfile-wrong.keyx` | | another valid XML v2 key: wrong-key-file cases |
| `keyfile-v2-bad-hash.keyx` | | XML v2 with a wrong `Hash`: must fail with `invalid_key_file` |

Key files are derived from fixed labels (`SHA-256("vazie-keep test key file …")`), so they are
reproducible. `vectors.json` lists each key file's expected component in hex and 17
open-or-fail cases. Before writing, the generator checks each component against pykeepass. The
vaults were also opened with keepass-rs 0.15 on 2026-10-01; it agrees on all of them except
the bad-`Hash` file, which it accepts because it doesn't verify the attribute.

## `kdbx4/`

| File | Cipher | KDF | Format | Content / expectation |
| --- | --- | --- | --- | --- |
| `aes256-argon2d.kdbx` | AES-256 | Argon2d | 4.0 | full |
| `aes256-aeskdf.kdbx` | AES-256 | AES-KDF | 4.0 | full |
| `chacha20-argon2id.kdbx` | ChaCha20 | Argon2id | 4.0 | full |
| `chacha20-aeskdf-kdbx41.kdbx` | ChaCha20 | AES-KDF | 4.1 | minimal |
| `unicode-password.kdbx` | AES-256 | Argon2id | 4.0 | minimal, non-ASCII password |
| `leak-marker.kdbx` | ChaCha20 | Argon2id | 4.0 | master password, entry password and a protected custom field all equal `VAZIE_KEEP_SECRET_DO_NOT_LEAK_42`; leak tests search every formatted value for it |
| `corrupted-payload.kdbx` | | | | one bit flipped in block 0 → integrity check failed |
| `invalid-header-hmac.kdbx` | | | | one bit flipped in the header HMAC → invalid credentials |
| `tampered-header.kdbx` | | | | one bit flipped in the master seed → corrupted (header SHA-256) |
| `truncated.kdbx` | | | | cut inside the first block → corrupted |
| `unsupported-version-3.1.kdbx`, `-5.0` | | | | version field patched → unsupported version |

The "full" content covers:

- nested groups (three levels) and an empty group;
- a protected password in every entry, a protected custom field, plain and empty custom fields;
- Unicode in group and entry names, usernames, passwords, URLs and notes;
- leading and trailing whitespace, tabs and newlines;
- XML-special characters (`<`, `&`, quotes).

`vectors.json` holds the expected result for every file and password pair. It was written by
hand from the generator's inputs, not from the reader's output.

**Passwords in `vectors.json`** (`correct horse battery staple`, `Tr0ub4dor&3`, a Unicode
phrase) are synthetic test data. They protect vaults that contain only invented values, so they
are not secrets.

**KDF parameters are deliberately weak** (Argon2: 1 MiB, 2 iterations, parallelism 2; AES-KDF:
1 000 rounds) so the suite runs in milliseconds. Never use them for a real vault.

### Source and license

- **Writer:** [pykeepass](https://github.com/libkeepass/pykeepass) 4.2.0 (GPL-3.0), an
  implementation independent of ours. It is used only as an external dev tool and is not
  distributed or linked with Vazie Keep. The generated `.kdbx` files are data we created, under
  this repository's licence ([LICENSE](../../LICENSE)).
- **Script:** `tooling/test-vectors/generate_kdbx4.py`. Cipher, KDF and version are set by
  editing the header containers before pykeepass saves.
- **Cross-check (2026-09-30):** keepass-rs 0.15.0 decrypted the crypto layers of all positive
  files and reported the same failure class for `corrupted-payload`, `invalid-header-hmac` and `tampered-header`. It rejects the "full"
  files' XML only because its schema requires contiguous `<String>` elements, which our reader
  deliberately tolerates.
- `SHA256SUMS` pins the committed bytes.

### Reproduce

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r tooling/test-vectors/requirements.txt
```

```bash
.venv/bin/python tooling/test-vectors/generate_kdbx4.py
```

Seeds and IVs are random, so regenerated files differ byte-for-byte, but the decrypted content
and `vectors.json` stay valid. Commit regenerated files together with the new `SHA256SUMS`.

A vault written by KeePassXC itself is not included yet: KeePassXC CLI cannot choose the cipher
or KDF and was not available on the machine that produced this suite. Adding
`keepassxc-cli db-create` + `add` output is the next vector task.

## Rules

- Everything here is synthetic. **Never commit real vaults, passwords, keys or personal data.**
- Vault files made for vectors use throwaway passwords, and the vector records them. A password
  written next to a vault that holds nothing is not a secret.
- Say where each binary vector came from (KeePassXC, KeePass 2.x, pykeepass, keepass-rs) and the
  exact tool version. Cross-implementation files are the point.
- Vectors are append-only once a client ships. Fix a wrong vector by adding a new one and
  documenting why.
